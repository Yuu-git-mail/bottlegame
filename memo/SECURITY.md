# メモ（memo/）の守り

このページは、iPhone などのブラウザの中だけで使う一時的なメモ帳です。
書いた内容はその端末のブラウザの保存領域（IndexedDB、名前 `memo`）にだけ、その端末で作った鍵で暗号にして置き、どこにも送りません。

## 書いた内容が外へ出ない仕組み

1. 送る処理がない
   本文を扱うのは IndexedDB への読み書きだけ。fetch・XHR・WebSocket・sendBeacon・フォーム送信はコードにない。
   外部のスクリプト・フォント・画像・解析・広告も読み込まない。ページの中身は index.html 1 枚で完結している。
2. 仮に何かが紛れ込んでも、ブラウザが外への通信を止める（CSP）
   `default-src 'none'` と `connect-src 'none'` で、ページからの通信と外部の読み込みを全部禁止している。
   スクリプトとスタイルはハッシュ（sha256）で 1 つずつ許可しているので、HTML に別のスクリプトを差し込まれても動かない。
   `require-trusted-types-for 'script'` で innerHTML などの文字列から HTML を作る経路も閉じている（対応ブラウザのみ）。
   `referrer` は送らない。
3. 書いた文字を HTML として扱わない
   表示は `textContent` だけ。行の書き直しは文字だけを受け付ける（`plaintext-only`、貼り付けも文字に直す）。
   保存の中身は読み込むときに形を確かめ、合わないものは捨てる。
4. 他のサイトの枠（iframe）に入れられたら動かない
   枠の中で開かれると、画面を空にしてメモを読み込まない。
5. Service Worker（sw.js）はオフライン起動の控えだけ
   このアプリ自身の 5 ファイル（HTML・manifest・アイコン 2 つ）だけを同じサイトから取って控える。
   それ以外の通信には関わらず、メモの本文も扱わない。

## 保存の暗号化

- 初めて開いたとき、ブラウザの WebCrypto で AES-GCM 256 ビットの鍵を作る。鍵は `extractable: false`（中身を取り出せない形）で作り、
  IndexedDB に CryptoKey のまま置く。ページのコードからも鍵の中身は読めず、使えるのは「この鍵で暗号化・復号して」と頼むことだけ。
- 付箋の一覧と書きかけは、保存のたびに新しい 12 バイトの IV で AES-GCM 暗号にしてから IndexedDB に置く。平文はどこにも書かない。
- 前の版（平文の localStorage `memo_v1`）が残っていれば、読み込んで暗号で書き直したあと平文を消す。
- 守れるもの: 保存領域のファイルやバックアップを抜き出されたときに、鍵のない所では読めない。鍵はこの端末のこのブラウザの中にしかない。
- 守れないもの: このページ自身（または同じサイトのページ）の上で悪いコードが動けば、ブラウザに復号を頼めるので読める。
  だから暗号化は「配る側を書き換えられない」こととセットで意味がある。下の「残る弱点」を参照。
- Face ID やパスコードには結び付けていない。端末を開けて Safari を操作できる人には見える。
  WebAuthn の PRF（パスキー）で鍵を Face ID に結び付ける道はあるが、パスキーの作成という説明の要る手順が増え、iCloud キーチェーンで他の端末に同期もされるので採らなかった。

## 確かめた結果（2026-10-26）

- 公開ページで文字を書き、リストへ入れ、開き直し、コピーまでの通信を記録した。
  書いている間の通信は 0 件。開き直しで出たのは同じサイトのアプリのファイルの GET だけで、書いた文字を含む通信はなかった。
- 悪いコードが動いた場合を想定し、ページ内から fetch・sendBeacon・WebSocket・外部画像・innerHTML を試した。全部 CSP と Trusted Types で止まり、外へ出た通信はなかった。
- 保存領域に `<img src=… onerror=…>` を入れても、文字として表示されるだけで画像も読み込みも起きなかった。
- iframe に入れると中身が空になった。
- 暗号化: 鍵は extractable=false。保存した暗号文のバイト列に、書いた文字（「牛乳」の UTF-8）は現れなかった。localStorage は空。平文の旧データは取り込み後に消えた。

## 量の試験（2026-10-26、PC の Chrome。iPhone 17 世代なら近い桁のはず）

書く→リストへ→済み を本物の操作で 200 回繰り返し、開き直しても 200 件が残ることを確かめた。
済みを積み上げた状態を作り、重さを測った。

| 件数 | 暗号文 | 開く | 1 文字打つ | 済みにする | 済みを開く |
|---|---|---|---|---|---|
| 1,000 | 0.1 MB | 26 ms | 0.08 ms | 35 ms | 4 ms |
| 10,000 | 1.2 MB | 32 ms | 0.07 ms | 40 ms | 4 ms |
| 40,000 | 4.9 MB | 89 ms | 0.08 ms | 84 ms | 30 ms |
| 100,000 | 12.3 MB | 169 ms | 0.10 ms | 160 ms | 6 ms |

- 打つたびに保存するのは書きかけだけなので、件数が増えても打つ速さは変わらない。
- 済みは開いたときだけ、新しい方から 300 件まで描く。古い分は「ほかに古い済みが n 件」と数だけ出す（消してはいない）。
- 1 日 20 件書いても 1 年で約 7,300 件。10 万件は 10 年以上先。
- 前の版は localStorage（1 サイト約 5 MB、約 5 万件で満杯、満杯になると黙って保存に失敗）だった。IndexedDB に移したので、この上限はなくなった。
  保存に失敗したときは「保存できませんでした」と出す。

確認は PC の Chrome（iPhone の画面幅をまねたもの）で行った。iPhone の Safari 実機での通信計測はまだ。

## 残る弱点（正直に）

- 配っている場所が書き換えられたら守れない
  ページは GitHub Pages から配っている。GitHub アカウントやリポジトリを乗っ取られて index.html と sw.js を書き換えられると、
  CSP ごと消され、次に開いたときに中身を読むコードが届く。Web のページである以上、これはページの側では防げない。
  守りは配る側（アカウントの二段階認証・パスキー、鍵の管理、main の保護）にかかっている。
- 同じサイトの他のページと保存領域を共有している
  `yuu-git-mail.github.io` の下のページはすべて同じ保存領域を見る。今あるページに外部スクリプトはないが、
  将来どれかに広告や解析を入れると、Safari で開いたメモを読まれ得る。
  ホーム画面に追加して使う分は、iOS では Safari と保存領域が分かれる。
- 端末側で消えることがある（Safari の自動の片付け）
  - 設定で Safari の履歴と Web サイトデータを消すと、鍵ごと消える。復元はできない。
  - Safari のまま、操作しない日が 7 日ほど続くと、サイトの保存がまるごと消されることがある（ITP の 7 日上限）。
    ホーム画面に追加した Web アプリは数え方が別で、実際に使った日だけ数える。
  - 端末の空きが足りないときや全体の上限を超えたときは、最後に使ったのが古いサイトから順に消される（WebKit の方針）。
    `navigator.storage.persist()` を呼んでおり、WebKit は「ホーム画面の Web アプリとして開かれているか」などを見て許可する。
    許可されると、この自動の片付けの対象から外れる。
  - 機種変更やバックアップからの復元で、鍵が新しい端末に移るかは確かめていない。移らなければ読めないので、引き継げない前提で使う。
  - 大量に積み上げても重さで消されることはない。消される条件は「容量の逼迫」「長く使っていない」「人が消す」の 3 つで、使っているサイトほど残る。
- 「まだの分をコピー」を押すと、済みでない行が 1 件 1 行の素の文字でクリップボードに入る（純正メモ帳で ○ にしやすい形）。Apple 製品間のユニバーサルクリップボードが有効なら、同じ Apple アカウントの他の端末へ渡る。押さなければ起きない。

## 直すとき

`<script>` か `<style>` の中身を変えたら、`python3 scripts/memo_csp.py` で CSP のハッシュを書き直す。
`--check` でずれていないか確かめられる。忘れるとブラウザがスクリプトを止めてページが動かなくなる。
